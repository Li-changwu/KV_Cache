# M3.7 真实 KV 张量复制原型说明

## 目标

M3.7 的目标是把 M3.6 的空操作连接器向前推进一步：不再只记录“将要复用哪些块”，而是能够在本地文件中保存一小段分页 KV 张量，并在下一次请求中按块加载回 vLLM 的分页 KV 缓冲区。

这个阶段仍然不是百万上下文性能实验。它验证的是最小工程事实：正确性键、块对齐、张量布局、清单文件和加载失败路径能不能被可靠表达。

## 已实现内容

新增 `benchmarks/m3/tensor_store.py`：

- `KVTensorStore`：按 `prefix_id` 写入本地目录。
- `KVBlockManifest`：记录前缀编号、令牌范围、正确性键、块大小、布局和每层张量文件。
- `block_slot_mapping()`：把 vLLM 块编号转换成扁平槽位编号。
- `extract_blocks_from_layer()`：从分页 KV 张量中抽取指定块。
- `copy_blocks_into_layer()`：把已保存的块复制回目标分页 KV 张量。

扩展 `benchmarks/m3/noop_connector.py`：

- 继续保留无存储路径，兼容 M3.6 的空操作冒烟。
- 配置 `m3_tensor_store_path` 后启用本地张量存储。
- 连接器元数据现在携带正确性键、前缀编号、令牌编号、块编号和操作类型。
- `save_kv_layer()` 可以保存每层 KV 张量。
- `start_load_kv()` 可以把已保存张量加载回已分配块。
- 加载失败会通过 `get_block_ids_with_load_errors()` 暴露对应块编号。

扩展 `benchmarks/m3/http_sidecar.py`：

- `kv_transfer_params` 增加 `store_prefix_id` 和 `store_token_end`，让连接器知道本次请求结束后应该把哪个前缀范围保存成清单。

## 当前覆盖的路径

当前只覆盖普通分页 KV 的块级复制路径，重点面向 Qwen2.5-14B 的 FlashAttention 与 `NHD` 布局。

已覆盖的失败场景：

- 令牌数不是块大小整数倍时拒绝。
- 正确性键不匹配时拒绝加载。
- 布局不匹配时拒绝加载。
- 连接器加载失败时上报失败块编号。

下一步应做一个很小的在线冒烟：

1. 启动 Qwen2.5-14B，启用自定义连接器和 `m3_tensor_store_path`。
2. 发送第一轮短提示词，请求经过前置代理，连接器保存本地清单与张量。
3. 发送第二轮共享同一前缀的短提示词，请求经过前置代理，连接器加载已保存块。
4. 检查连接器日志、清单文件、失败块集合和请求返回。
5. 只在链路稳定后再比较首个结果等待时间。
